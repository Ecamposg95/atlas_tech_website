ATLAS OPERATING MODEL
--
Análisis legal especializado integrado al modelo
--
ATLAS TECH
--
--
El trabajo de Atlas se estructura con una revisión legal especializada en software empresarial, propiedad intelectual, confidencialidad, privacidad, seguridad y operación SaaS en México.
--
--
No se trata solo de “hacer código”: se trata de proteger datos, separar activos, regular licencias, definir continuidad y evitar ambigüedad contractual.
--
--
IP
--
Background technology, custom developments, licencias y cesiones.
--
--
Privacy
--
Datos personales, roles responsable/encargado y medidas de seguridad.
--
--
Confidentiality
--
Secretos industriales, información estratégica y acceso restringido.
--
Nota: material estratégico de Atlas; no sustituye dictamen jurídico externo sobre contratos ya firmados.

=== ppt/slides/slide7.xml ===
ATLAS OPERATING MODEL
--
Propiedad intelectual: separar activos evita conflictos
--
ATLAS TECH
--
--
La pregunta correcta no es “¿de quién es todo?”. La pregunta correcta es: ¿qué capa estamos analizando, qué existía antes, qué se creó para el cliente y qué se licencia?
--
--
Datos del cliente
--
Propiedad/control del cliente; Atlas procesa bajo instrucciones.
--
--
Materiales del cliente
--
Logos, catálogos, procesos, documentación y contenido propio.
--
--
Tecnología previa Atlas
--
Arquitectura, componentes, frameworks propios y know-how reusable.
--
--
Configuración específica
--
Parámetros, flujos y reglas del tenant del cliente.
--
--
Desarrollos custom
--
Se clasifican por SOW: licencia, cesión o uso limitado.
--
--
Software de terceros
--
Sujeto a licencias open source/comerciales; no se cede lo que no se posee.
--
--
--
IP Schedule
--
El documento que clasifica activos, licencias, derechos de uso, restricciones, excepciones, entregables y escenarios de continuidad.
--
• Reduce ambigüedad
• Protege plataforma Atlas
• Da certeza operativa al cliente
• Distingue implementación de cesión de IP
--
Referencia normativa: LFDA vigente — protección de programas de cómputo como obras literarias, código fuente/objeto y reglas de obra por encargo.

ATLAS OPERATING MODEL
--
Confidencialidad: jurídico + técnico + organizacional
--
ATLAS TECH
--
--
Para que la confidencialidad sea defendible, debe existir una combinación de acuerdos escritos, clasificación de información y controles reales de acceso.
--
--
01
--
NDA bilateral
--
Define información confidencial, excepciones, vigencia y uso permitido.
--
--
02
--
Clasificación
--
Datos, código, arquitectura, procesos, precios, credenciales y secretos.
--
--
03
--
Controles
--
Acceso need-to-know, MFA, repos privados, logs, ambientes y backups.
--
--
--
--
En software industrial, la información sensible puede incluir procesos, precios, clientes, proveedores, arquitectura, credenciales, vulnerabilidades y roadmap.
--
Referencia normativa: LFPPI vigente — secreto industrial requiere ventaja competitiva y medios suficientes de confidencialidad/acceso restringido.

ATLAS OPERATING MODEL
--
Privacidad y seguridad: datos gobernados, no solo almacenados
--
ATLAS TECH
--
--
Modelo mínimo para proyectos B2B con datos personales y datos de negocio
--
--
Mapa de datos
--
Qué datos existen, quién los provee, dónde viven y para qué se usan.
--
--
Roles
--
Cliente como responsable; Atlas como encargado cuando procesa por instrucciones.
--
--
Medidas
--
Administrativas, técnicas y físicas: acceso, cifrado, logs, backups y continuidad.
--
--
Incidentes
--
Procedimiento de respuesta, notificación, mitigación y evidencia.
--
--
La seguridad debe poder explicarse en lenguaje ejecutivo: quién accede, a qué, para qué, desde dónde, con qué trazabilidad y bajo qué responsabilidad.
--
Referencia normativa: LFPDPPP vigente — tratamiento legítimo, responsable/encargado, confidencialidad y medidas de seguridad.

IA, open source y supply chain: control sobre lo que usamos

ATLAS TECH

Un software moderno no es solo código propio. Incluye librerías, frameworks, servicios cloud, modelos de IA, paquetes, APIs y proveedores.

Modelo / API IA

política de datos, logs, retención, entrenamiento, región

Dependencias OSS

licencia, versión, vulnerabilidades, mantenimiento
--

Servicios cloud

región, backups, credenciales, continuidad, subprocesadores
--
--
Código Atlas
--
repositorio, ramas, owner, pruebas, changelog
--
--
Datos cliente
--
finalidad, acceso, exportación, eliminación, portabilidad

Esto protege a DASIC y también protege el core reutilizable de Atlas.

=== ppt/slides/slide11.xml ===
ATLAS OPERATING MODEL
--
Costos, pagos y alcance: separar conceptos
--
ATLAS TECH
--
--
Un pago puede cubrir implementación, desarrollo, soporte o licencia. No debe confundirse automáticamente con una compra total de la tecnología subyacente.
--
--
Implementación
--
configuración, migración, puesta en marcha
--
--
Desarrollo
--
capacidad de ingeniería y construcción custom
--
--
SaaS / licencia
--
derecho de acceso y uso
--
--
Soporte / SLA
--
mantenimiento, continuidad y respuesta
--
--
Regla comercial: desarrollo ≠ cesión de IP ≠ exclusividad ≠ acceso a código fuente. Cada concepto debe valorarse y documentarse por separado.
--
Herramientas: SOW + Change Order + IP Schedule + SLA + anexo de costos y saldos.
